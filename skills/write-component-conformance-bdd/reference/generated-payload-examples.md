# Generated Payload Examples

This document contains example payload patterns generated by the Component BDD Generator.

These examples are provided for illustration only.

Payload structure, field names, field types, array names, required attributes, and object hierarchy must always be derived from the OpenAPI specifications referenced by the Component Specification YAML.

Do not generate payloads by copying or adapting these examples.

---

# OpenAPI Authority

For payload generation:

1. Component Specification YAML identifies APIs.
2. OpenAPI specifications define payload structure.
3. Payload examples illustrate patterns only.

When examples conflict with OpenAPI specifications, OpenAPI specifications always take precedence.

# Payload Generation Principles

1. Generate payloads from the highest supported OpenAPI version and verify compatibility with lower supported versions where possible.
2. Use the minimum payload that validates against the OpenAPI POST request schema.
3. Prefer required fields only.
4. Use `__VALID_ID__` and `__VALID_HREF__` in success target payloads.
5. Use `non-existent-id` and `non-existent-href` in failure target payloads. Do not introduce alternative invalid placeholder values unless explicitly required by the CTK runtime contract.
6. Use additional setup payloads only when the dependent API resource itself requires another referenced resource.

---

# Payload Validation

Generated payloads must:

- validate against the resolved POST request schema
- satisfy required attributes
- use valid scalar types
- use valid enum values
- use valid array names
- use valid object hierarchy

Payloads failing schema validation must not be emitted.

---

# Base Payload Rules

Base payloads:

- are generated from the dependent API POST schema
- must not contain runtime placeholders
- must create a valid dependent resource

# Target Payload Rules

Target payloads:

- are generated from the exposed API POST schema
- must contain dependency references
- use runtime placeholders in success variants
- use invalid identifiers in failure variants
